# AI Usage

## Overview

Kestrel has been developed with substantial assistance from generative AI.

ChatGPT by OpenAI has been used throughout the project for activities including:

- drafting and revising source code;
- drafting Docker and service configuration;
- designing Activepieces workflows;
- troubleshooting implementation problems;
- discussing architecture and security decisions;
- drafting project documentation;
- identifying edge cases and possible future work;
- reviewing exported configuration for portability and accidental disclosure.

AI assistance is not incidental to the development process. A significant portion of the literal
code and documentation in this repository originated as model-generated drafts.

## Human contribution

The project is conceived, directed, integrated, tested, and maintained by Adrien Abbey.

Human contributions include:

- defining the purpose and scope of Kestrel;
- identifying the real-world task-management problems the system is intended to address;
- establishing Nextcloud Tasks as the authoritative task store;
- defining task semantics such as start-date, deadline, priority, and stale-work behavior;
- choosing the local-first and least-privilege architecture;
- defining security and authority boundaries;
- selecting and operating the underlying infrastructure;
- supplying requirements and constraints to the AI;
- evaluating proposed approaches;
- running commands and configuring services;
- testing generated implementations against real systems;
- reporting failures and unexpected behavior;
- accepting, rejecting, or modifying proposed designs;
- determining the project's roadmap and final behavior.

These activities materially shape the resulting software even when the literal implementation text
was generated by an AI system.

## AI contribution

ChatGPT has frequently acted as a development assistant capable of producing complete candidate
implementations rather than merely answering isolated questions.

Depending on the task, AI contributions have included:

- substantial portions of implementation code;
- complete or near-complete configuration blocks;
- algorithm and policy implementations;
- documentation drafts;
- debugging hypotheses;
- refactoring proposals;
- security-model wording;
- installation and onboarding material.

Some generated material has been modified extensively through iteration. Other material has been
accepted largely as generated after functional testing and discussion.

The repository therefore should not be described as wholly hand-written by its human maintainer.

## Review and responsibility

AI-generated material is treated as a proposal, not as an authoritative source.

During development, generated results are commonly evaluated through:

- discussion of intended behavior;
- inspection of relevant output;
- execution against the actual environment;
- repeated testing;
- comparison with observed system behavior;
- correction when results are wrong or unsuitable.

However, not every generated line has necessarily received exhaustive independent code review.

Users should therefore apply the same caution appropriate to other experimental software, and
especially to code that interacts with personal data.

Adrien Abbey accepts responsibility for deciding what material is incorporated into Kestrel and for
the project's published behavior and direction.

## Attribution

AI assistance has primarily been provided through ChatGPT by OpenAI.

ChatGPT is acknowledged as a development tool and drafting assistant rather than represented as a
human co-author or project maintainer.

The repository's commit history records the human maintainer responsible for accepting and
integrating changes; it should not be interpreted as evidence that every committed line was manually
authored by that person.

## Why this disclosure exists

Kestrel is a personal open-source project rather than an academic assignment, and there is no intent
to claim unaided authorship.

This disclosure exists to:

- accurately represent how the project was produced;
- give appropriate credit to the tools that materially contributed;
- avoid overstating the human author's role in drafting implementation text;
- distinguish human design and engineering judgment from generated implementation;
- help users evaluate the provenance and review level of the software.
